# IPv4 VLSM 地址规划台

本地运行的 IPv4 可变长子网掩码（VLSM）地址规划工具。基于 **React 18 + TypeScript + Vite**，纯前端计算，数据不离开本机。

## 功能

- **录入父 CIDR**（如 `192.168.10.0/24`）。
- **保留区**：以 CIDR 形式录入，不参与需求分配。
- **需求列表**：每项填写「主机数」和**可选**的固定网段（CIDR）。
- **自动网段容量**：按「可用主机数 = 地址数 − 2」（扣除网络地址与广播地址）取最小 2 的幂分块，**最小为 /30**（4 个地址、2 个可用主机）。
- **校验规则**：
  - 保留区和固定网段必须完全位于父网段内；
  - 保留区与固定网段之间、以及彼此之间**互不重叠**；
  - 固定网段的可用主机数必须足够容纳该需求，否则报错并给出实际可用数。
- **分配算法**：自动需求按规模**从大到小**排序，同规模按**录入顺序**，在保留区/固定网段/已分配网段之外选取**最低的、满足前缀边界对齐**的空闲块；放不下时在页面上说明原因（最大连续空闲块大小 / 对齐不满足）。
- **比例地址条**：按地址数比例区分 🟠 保留、🟣 固定、🟢 自动、⚫ 空闲四类区域。
- **点击交互**：点击地址条色块或明细表任意行，展示该项的**网络地址、广播地址、可用范围、容量与浪费量**。
- **基线对比**：将当前无输入错误的规划保存为基线，修改父 CIDR / 保留区 / 需求后，按需求的**稳定 ID** 自动对比并标记：
  - **新增**、**删除**、**未变**；
  - **迁移**：网段 CIDR（地址区间）改变即迁移；容量同时变化时追加**扩容 / 缩容**幅度；
  - **未分配**（基线能分配、当前放不下）与**恢复分配**（基线失败、当前成功），并保留失败原因；
  - 按地址区间汇总**新占用 / 释放 / 仍占用**范围（区间自动合并、**重叠部分不重复计数**），并给出**净地址变化**（新占用 − 释放）。
  - 基线只保存在**当前浏览器会话**（`sessionStorage`，关闭标签页即失效，不上传任何服务端），提供「**重建基线**」（用当前规划覆盖）与「**清除基线**」操作；输入非法时**保留基线并暂停对比**，修正后自动恢复。
- **导出 JSON**：一键导出包含父网段、统计、全量网段明细及失败原因的 JSON 文件（时间戳命名）。

## 一条命令启动（Docker Compose）

无需准备 Node 环境，安装 Docker 后在项目根目录执行：

```bash
docker compose up -d --build
```

启动成功后，在浏览器打开：

> **http://localhost:8080**

首次构建约需 1–2 分钟（拉取 node/nginx 镜像并编译静态资源）；之后再次启动只需：

```bash
docker compose up -d
```

查看日志 / 停止：

```bash
docker compose logs -f
docker compose down
```

> 端口占用时修改 `docker-compose.yml` 中的 `"8080:80"`，例如改为 `"9090:80"`，随后访问 http://localhost:9090 。

## 使用示例

点击页面上的「**载入示例**」可快速体验，示例等价于：

| 名称 | 主机数 | 固定网段 | 类型 / 规划结果 |
| --- | --- | --- | --- |
| 核心交换链路保留 | — | `192.168.10.0/28` | 保留（0–15） |
| 办公区 VLAN | 100 | | 自动（128/25，126 可用） |
| 机房 VLAN | 40 | | 自动（64/26，62 可用） |
| 监控固定段 | 25 | `192.168.10.32/27` | 固定（32–63，30 可用） |
| 设备管理 | 2 | | 自动（16/30，2 可用） |

自动需求按规模从大到小处理：`/25` 在最低对齐地址 128 落位（16–31 的间隙放不下）；`/26` 落到 64；`/30` 最后填入最低空闲间隙 16。最终保留 16 + 固定 32 + 自动 196 = 244 个地址，剩余 12 个空闲（20–31、192–255），利用率 95.31%，浪费 53 个地址。

## 基线对比操作说明

1. 先得到一份**没有输入错误**的规划（分配失败的需求可以存在，会一并记入基线）。
2. 在「**④ 基线对比**」面板点击「**保存为基线**」。面板会显示基线保存时间与基线父网段。
3. 正常修改父 CIDR、保留区或需求（增删条目、改主机数、改/加固定网段均可），对比结果实时刷新：
   - 顶部色块给出 **新增 / 删除 / 迁移 / 未分配 / 恢复分配 / 未变** 的计数；
   - 下方地址卡片列出**新占用、释放、仍占用**的具体地址区间（相邻区间自动合并）与**净地址变化**；
   - 明细表按需求逐条列出基线段、当前段与容量变化；页面底部的「网段明细」表也会按行追加同款标记。
4. 想以当前结果作为新的参照，点击「**重建基线（覆盖当前）**」；不再需要时点击「**清除基线**」。
5. 输入非法（如 CIDR 写错、网段越界或互相重叠）时，面板提示「**保留基线并暂停对比**」，基线不会丢失；把输入改回合法状态后对比自动恢复。

> 稳定 ID 指每条保留区/需求在页面内的内部标识，用「＋ 添加」生成的行拥有独立 ID；删除某行即视为该 ID 被删除，改名、改主机数、改 CIDR 都不会改变它的 ID。
>
> 基线通过浏览器 `sessionStorage` 仅保存在**当前标签页会话**中：刷新页面仍在，关闭标签页或浏览器后清除；数据不离开本机。

## 分配规则说明

1. 需求主机数 `h` → 网段大小取满足 `size − 2 ≥ h` 的最小 2 的幂，`size ≥ 4`，即前缀 `≤ /30`。
2. 先登记保留区和固定网段（校验包含性、互不重叠、固定段容量足够）。
3. 自动需求按所需前缀从小到大（规模大→小）排序；所需前缀相同时保留录入顺序。
4. 对每个需求，按地址升序扫描空闲间隙，取第一个能容纳该块、且起始地址对齐到其前缀边界的间隙；这就是「占用区之外的最低对齐空闲地址」。
5. 若所有间隙都无法容纳，报告：当前最大连续空闲块、所需块大小与前缀，或边界对齐不满足的原因；其余需求继续尝试分配（互不影响）。
6. 浪费量 = 自动/固定网段的（可用主机数 − 需求主机数）；保留区与空闲区不计入浪费统计。
